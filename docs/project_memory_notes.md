## Stage B and links

- The [Stage B run](../experiments/results/longmemeval_shared_workspace.md) covered 601 workspaces and 18,177 reads. There were zero observed leaks, all rankings matched their visibility reference, and all 2,704 visible canaries were found. Owner RR@10 was 0.6464 with filtering before ranking and 0.6568 with filtering after ranking over all candidates. The difference of −0.0104 was within the preset 0.02 margin.
- The [`links-ignore` fault](../experiments/results/longmemeval_shared_workspace_fault_links_ignore.md) exposed 1,450 hidden link endpoints in 408 reads. Only 175 reads matched their reference. All six Stage B fault controls showed their expected pattern.
- Stage B uses real text in constructed workspaces with silent reads. A subsequent [cross-user dispute experiment](../experiments/results/longmemeval_cross_user_disputes.md) tested exact restatements. The reworded pairs await independent review.
- Rebuild should carry links over, preserving source IDs and audience/workspace scope. Rebuild drops links whose other end has no live counterpart (retracted without a rebuild, or pruned). It does not check reader scope: reads filter links by audience as for any link.

## Retraction

- Synthetic canaries: 500/500 trials held determinism, specificity, erasure, exact-source rebuild, and keyed-backup checks.
- Real LongMemEval text: 200/200 trials held determinism, specificity, erasure, read isolation, exact-source rebuild, and keyed-backup checks. Undeclared copied text remains a known limitation (398/398 such copies stayed readable).
- Treat links/source lists as required rebuild lineage. They are the mechanism that lets retraction identify stale derived memories; text copied without declared provenance cannot be safely rebuilt or erased.

## Implementation follow-up

- `MemoryStore.rebuild_stale` now carries links from a stale derived memory to its rebuilt replacement. The other end must be live, or stale with a live rebuild (the link then points at the rebuild). Supersession edges remain separate; links to pruned endpoints, or to endpoints retracted without a rebuild, are not resurrected.
- Added regression tests for live-link carryover, both-ends rebuild in either order, no carry to a pruned or non-rebuilt neighbour, and atomicity. The full suite (435 tests) passes.
- Run 2 (first carry-over): all 7 rules held; linked reads identical 896, same-ranking 4, different 0. Review found a gap where two linked memories both lose a source (the link was lost because the link was copied only if the other end was live at that moment); the 4 residual queries disappeared after the fix, which is consistent with that cause but was not traced query by query. Fixed: a stale end now stands for the memory that rebuilt it, and links are carried in the same transaction as the rebuild.
- [Run 3](../experiments/results/longmemeval_retraction.md) (2026-11-24): all seven rules held in 200/200 trials. Both linked (900/900) and unlinked (898/898) query results matched the never-written reference, and all four injected faults were detected. The rebuilt memories use extractive joins and declared sources. Run 1's reports are in `experiments/results/longmemeval_retraction_run1_superseded/`.

## LongMemEval v3

- The [superseded run 1](../experiments/results/longmemeval_v3_run1_superseded/longmemeval_v3.md) used 68 questions and 47 current-value questions. The [recorded run 2](../experiments/results/longmemeval_v3.md) used 68 questions and 45 current-value questions. All three controls held in run 2. Across the six two-piece questions in run 2, lexical first hit@10 stayed 1.000 when updates were applied, while all required@10 fell from 1.000 to 0.167. Treat each run as a result for its annotation snapshot and the whole-turn archive policy.
- The [reviewed annotations](../eval/longmemeval_knowledge_update_annotations_v3_reviewed.json) have 68 included questions, 45 current and five context. Eight of the original 11 former-evidence cases still require a turn that is superseded as the current value. Three proposed edges were removed from the update set: Silver eligibility vs Gold status, baseball counts from different windows, and Wednesday with Juan vs Thursday with Maria. The morning coffee update and required evidence now use the confirmation. The Apex update points to the explicit statement of the new current goal.
- The reviewed JSON preserves caution flags for ambiguous chronology, wording, and approximate answers. Use those flags when selecting detector controls or sensitivity cohorts. The [real-text cross-user dispute experiment](../experiments/results/longmemeval_cross_user_disputes.md) passed all six checks in 470/470 trials with staged speakers and exact text matching. Paraphrase equivalence remains open.
- A separate [AI-audited v3 revision](../eval/longmemeval_knowledge_update_annotations_v3_ai_audited_2026-11-25.json) implements the four newly proposed exclusions above and removes the unsupported shoe-rack supersession edge for `07741c44`, leaving seven of the original 11 older-required overlaps. Its 64 included sets and six exclusions passed conversion validation. The [category-approved snapshot](../eval/longmemeval_knowledge_update_annotations_v3_category_approved_2026-11-25.json) records the project owner's acceptance of the nine category choices without changing the underlying evidence and relation annotations. Those remain provisional; recorded earlier v3 results refer to a different annotation snapshot.
- The [category-approved v3 run](../experiments/results/longmemeval_v3_category_approved_2026-11-25.md) includes 64 questions: 44 current-value and seven older-required supersession cases. All three controls held. Applying supersession changed all-required@10 on current questions by 0.000 in both lexical and MiniLM retrieval; it reduced all-required@10 for older-required cases by 1.000 lexical and 0.857 MiniLM (paired p 0.016 and 0.031). Semantic minus lexical with updates kept was +0.031 over all 64 (p 0.625). This run used the cached MiniLM model through sentence-transformers 3.4.1. Earlier LongMemEval documentation cites 2.7.0, but the prior v3 runtime was not recorded, so cross-run version attribution is uncertain.
- The [category-approved detector baseline](../experiments/results/longmemeval_detector_baselines_category_approved_2026-11-25.md) covers 51 annotated update cases and 13 no-update cases. Both controls held; BM25 placed a true old turn among five candidates for 49/51 positive questions. At shipped thresholds, overlap recalled 0/44 current updates, ngram hash 11/44, and MiniLM 9/44. The latter two fired on 155/640 and 236/640 control turns; all three detectors failed the preset usability rule. The harness now probes the annotated confirmation turns for the coffee and Apex cases instead of earlier proposal turns and excludes those confirmations from control sampling, so the older detector report is not directly comparable. Update edges and required-evidence groups remain provisional.
- The [history retrieval pilot](../experiments/results/longmemeval_history_retrieval_pilot.md) passed all four controls. With supplied current intent and annotated update edges, lexical demotion lifted current RR@10 from 0.524 to 0.670 and preserved all-required@10 for seven of seven older-evidence questions. Whole-turn archiving preserved zero of seven in this cohort. The [independent review packet](longmemeval_evidence_review_packet.md) starts with those seven cases. It awaits reviewer ballots.
- The [paraphrase dispute pilot packet](longmemeval_paraphrase_review.md) has 48 draft pairs across 12 source families. Keep all variants from a family in one split. Human judgments and equivalence scoring are pending.
